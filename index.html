AN INDEPENDENT UNIX-LIKE SYSTEM

FIR

Free. Independent. Reproducible.

A small, opinionated operating system built around simple software, reproducible systems and giving the user control.

View source Project status

FIR takes inspiration from systems such as NixOS, while following its own path. The system is configured declaratively with config.fir and built from explicit inputs.

FIR is intentionally opinionated. It chooses sensible defaults instead of presenting five different ways to accomplish the same thing, while still allowing users to change those decisions when they want to.

The project follows KISS: keep the system understandable, avoid unnecessary abstraction, and build small components that do their jobs well.

## Principles

F · Free

FIR is free software. The system is developed in the open and aims to give users the freedom to study, modify, share and run the software they depend on.

I · Independent

FIR is its own project, not a downstream distribution or a product controlled by a company. Its direction is decided by its contributors and users.

R · Reproducible

The system is designed so that its configuration and build inputs can be described explicitly and rebuilt consistently. Reproducibility is a design goal, not an afterthought.

K · Keep it simple

FIR prefers small programs, straightforward interfaces and understandable implementations. Complexity needs a reason to exist.

## What's in the box

fir-utils

A compact collection of essential Unix utilities such as ls, cat, cp, mv, rm, mkdir and friends. Small programs, sensible defaults, and no kitchen sink.

Fern

FIR's init and service manager. Small, straightforward and responsible for one thing: getting services running and keeping them running.

Window manager

A simple Xorg window manager. One program, a small configuration, and no unnecessary machinery.

Package system

Declarative system configuration combined with an imperative interface for when you simply need a package right now. The goal is reproducibility without making everyday use painful.

## Configuration

FIR's system configuration lives in config.fir. The format is intentionally small: structured enough to describe a system, but simple enough that you can understand the parser. 

system {
    hostname = "firbox"

    packages {
        global = [
            "gcc"
            "make"
            "vim"
            "git"
        ]

        user = [
            "firefox"
            "mpv"
        ]
    }

    defaults {
        ls.long = true
    }
}

The configuration describes what you want. FIR takes care of building and activating it.

## Build, then switch

FIR is designed to be stubborn about changing a working system. A failed build should not leave the machine half-switched into an unknown state. 

$ fir build

$ fir switch
building configuration...
verifying build...
activating generation 12

$ fir rollback
activating generation 11

--force exists for situations where you explicitly want to bypass a safety check. FIR assumes that if you are going to do something dangerous, you should at least mean it.

Pre-alpha

FIR is very early in development. There is currently no installable release or ISO.
